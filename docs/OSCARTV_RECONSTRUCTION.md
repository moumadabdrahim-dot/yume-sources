# إعادة بناء تكامل OscarTV مع Yume

## الحالة والنطاق

هذا المستند يربط تدقيق التطبيق المفكك بالتنفيذ الحالي في مستودع الإضافة. درجات الإثبات المستخدمة هنا:

- **مثبت من التطبيق:** ظاهر في APK v1.1.5 أو في مساراته المفككة.
- **مثبت باختبار محلي:** سلوك الإضافة يعمل على بيانات الاختبار، ولا يثبت استجابة الخادم.
- **متحقق حيًا:** شوهد في طلب إلى الخدمة الفعلية.
- **غير محسوم:** لا تكفي الأدلة الحالية لإثباته.

التدقيق الساكن التفصيلي ومسارات الأصناف والأسطر موجودة في ملفات الاستخراج المحلية لدى المطوّر وملفات تتبع التشغيل. هذا التقرير يلخص ما يلزم لصيانة الإضافة دون نسخ شجرة التطبيق المفككة إلى مستودعها.

## هوية التطبيق وبنيته

المرجع الذي جرى فحصه هو إصدار OscarTV الرسمي v1.1.5، الحزمة `com.drama.mp4`، رقم الإصدار 15. أُخذ APK من مستودع الإصدار الذي يرتبط به موقع OscarTV الرسمي. بصمة ملف APK هي `5c7c7a50ae6ac72de596dbea0d2d8f3c1d6d3acff76d62bf0387f4cd3a3f29ad`، وبصمة شهادة التوقيع `6e2fcda8631eb49ebcba4ca8ef4c597abe84654c7d3e8096db32bdd21ecf763f`.

التطبيق Android أصلي، ويستخدم Retrofit/Gson وOkHttp لطبقة الشبكة. مصدر توقيع Iron داخل التطبيق يفوض العمل إلى دالة native، بينما يضيف interceptor الترويسات وتوقيت الخادم. التطبيق يقرأ إعداد النطاق النشط ويمتلك آلية تبديل/احتياط للنطاقات. لم تُثبت قائمة النطاقات الاحتياطية أو طريقة تحديثها كاملة بما يكفي لنشرها داخل إضافة عامة.

المراجع الرسمية المستخدمة للتحقق من هوية الإصدار:

- [صفحة تنزيل OscarTV](https://oscartv.app/downloads)
- [إصدار OscarTV v1.1.5](https://github.com/Oscar-TV/apk/releases/tag/v1.1.5)

## خريطة API إلى Yume Plugin API v2

| الوظيفة | مسار OscarTV | تنفيذ الإضافة |
|---|---|---|
| أفلام وبحث وصفحات | `/api/movies/` | `getCatalog` مع `search`, `page`, `limit` وفلاتر القائمة المسموح بها |
| مسلسلات وبحث وصفحات | `/api/series/` | `getCatalog` وهوية `series:<id>` |
| أنمي وبحث وصفحات | `/api/anime/` | `getCatalog` وهوية `anime:<id>` |
| تفاصيل فيلم | `/api/movies/show.php?id=…` | `getDetails` ويعرض روابط الفيلم عبر `getStreams` |
| تفاصيل مسلسل ومواسمه | `/api/series/show.php`, `/api/seasons/` | `getDetails` ثم يجلب صفحات حلقات كل موسم |
| حلقات مسلسل | `/api/episodes/`, `/api/episodes/show.php` | IDs أصلية من نوع `series_episode:<id>`، ولا تُشتق من رقم الحلقة |
| تفاصيل أنمي وحلقاته | `/api/anime/show.php`, `/api/anime/episodes/`, `/api/anime/episodes/show.php` | `anime:<id>` و`anime_episode:<id>`، مع دعم روابط المشاهدة على الأنمي الأب |
| روابط حلقة مسلسل | `/api/watch_links/?episode_id=…` | مسار بديل عندما لا تعيد تفاصيل الحلقة روابط مشاهدة |

تطابق الإضافة حقول العناوين والصور والتقييم والأنواع ومعرفات TMDB/IMDb عندما يرسلها Oscar. معرف Oscar الأصلي يبقى هو هوية المصدر، ويظل إثراء TMDB منفصلًا. فلاتر manifests لا تُرسل إلا إذا كانت ضمن مفاتيح endpoint المسموح بها في الإضافة.

## الطلبات والتوقيع

قاعدة API الافتراضية المعلنة في التطبيق هي `https://ostvapp.cam`. أزيلت خدمة التوقيع الخارجية `flech.tn` من مسار الإضافة؛ لم نجد ما يثبت أنها خدمة رسمية من OscarTV، لذلك لا تعتمد الإضافة عليها ولا ترسل إليها روابط أو بيانات طلبات. الإضافة تنفذ مسار التوقيع محليًا، وتستخدم ترويسات Iron ووكيل HTTP الذي يظهر في مرجع التطبيق، مع توقيع المسار الخام دون query.

اختبار `iron-signer.json` متجه حتمي لاختبار ثبات تنفيذ الإضافة. في تجربة Windows الحية بتاريخ 2026-10-15 استخدمت الإضافة توقيع Iron المحلي على المضيف المنشور `ostv-11-11.xyz`، وأعادت طلبات الكتالوج والتفاصيل والمواسم والحلقات وWatchLinks HTTP 200. المضيف المستخرج من إعداد التطبيق `ostvapp.cam` أعاد Cloudflare HTML 403؛ لم نغيّر المضيف المنشور أو طريقة التوقيع بناء على ذلك.

التحويلات في طلبات API يدوية حتى لا تنتقل ترويسات التوقيع إلى نطاق آخر. توجد إعادة محدودة لأخطاء الشبكة و502/503/504، ولا يعاد طلب 403. يُزامن فرق الساعة من `Date` ضمن حد يوم واحد. Yume نفسه يفرض مهلة وإلغاءً على مستوى تنفيذ الإجراء؛ جسر `fetch` لا يعرّض مهلة مستقلة لكل طلب إلى JavaScript.

لا توجد حاليًا قائمة host failover موثوقة داخل الإضافة. لا تُستخدم نطاقات احتياطية مستنتجة من اسم أو مسح نطاقات؛ يلزم مصدر تكوين رسمي يمكن التحقق منه وتحديد النطاقات المسموح بها قبل إضافة failover.

## تدفق التشغيل والوسائط

1. تعرض القوائم معرفات Oscar أصلية ذات بادئة نوع واضحة.
2. تفاصيل المسلسل تعيد حلقات مرتبة حسب الموسم ورقم الحلقة مع native IDs من استجابات Oscar.
3. `getStreams({mode:"options"})` يسرد WatchLinks دون حل كل wrapper. إذا أرسل Oscar معرّف WatchLink، يخزن token هذا المعرّف وهوية العنصر فقط؛ عند الاختيار يجلب الإضافة القائمة مجددًا وتطابق الرابط بالمعرّف لتستخدم URL حديثًا. لا يُحفظ الرابط الموقّع في token الجديد. الاستجابات القديمة التي لا تحمل معرّفات تبقى على token التوافق السابق، ولذلك لا يمكن تحديث URL فيها تلقائيًا.
4. يعتمد اختيار الرابط على النوع والحقول المدعومة: direct media، أو رابط HTTP عادي، أو deep link بصيغة `tdmvideo://` يحتوي `url=` HTTP(S). لا يمرر scheme مخصصًا إلى Media3.
5. resolver محدود العمق والدورات، ويتبع redirects المعتادة، ويفحص MIME/امتداد الوسيط. يدعم ممررات SeriesMP4 المحددة وروابط Yandex التي تظهر في اختبارات المرجع؛ لا يحتوي منظومة CloudStream عامة أو استخراجًا تعسفيًا لمواقع أخرى.
6. يحتفظ stream بهوية WatchLink وجودة المصدر وترويسات المشغل، ويعيد HLS كنوع HLS. لم يظهر في موديلات WatchLink المفحوصة حقل ترجمة منفصل؛ معلومات `subtitled` الظاهرة هي وصف نوع المحتوى، فلا تُخترع ترجمة أو URL لها.

التطبيق الأصلي يمرر اختيار المشاهدة إلى `ACTION_VIEW` ويدعم تسليم `tdmvideo` إلى TDM. هذا يثبت شكل handoff، لكنه لا يثبت أن كل wrapper يمكن حله داخل Yume أو أن TDM نفسه يطلب نفس المورد النهائي.

## أداء وحدود التشغيل

- Home: ثلاث قوائم متزامنة مع حفظ ترتيب الأقسام وعزل فشل القسم.
- تفاصيل المواسم: موسمان متزامنان، وصفحتان متزامنتان لكل موسم؛ أقصى دفعة صفحات الحلقات أربع طلبات.
- حل WatchLinks غير المحددة: خياران متزامنان مع المحافظة على ترتيب المصدر.
- خيارات البث lazy؛ لا تُجرى طلبات media قبل اختيار مصدر.
- لا تخزن الإضافة روابط تشغيل موقعة في cache دائم. Tokens الجديدة ذات ID لا تتضمن الرابط الموقّع، وتعيد جلب WatchLink المختار بعد الاختيار لتحد من الروابط المنتهية. التفاصيل ما زالت تجلب كل الحلقات عند طلب المسلسل، لذلك السلاسل الطويلة تعتمد على مهلة Yume وإتاحية صفحات Oscar.
- الطلبات الفاشلة لصفحة حلقة تُترك كصفحة ناقصة مع عزل الموسم؛ لا يمكن وسم الحلقة الناقصة داخل عقد API الحالي.

## تشخيص House of the Dragon S1E1

الاختبار الحي يشغّل `plugins/oscartv-v2.js` نفسه داخل harness Windows، ويبقي الرد الخام والروابط الموقعة في الذاكرة. في House of the Dragon S1E1 كان native ID للحلقة `series_episode:28718` وأعاد Oscar خمس روابط: `متعدد` (109640)، ثم `سيرفر مباشر B2` بالجودات 1080p (109636)، 720p (109637)، 480p (109638)، و360p (109639). لم تتضمن أسماء المصدر نص `Via — Server 4`. Yume يعرض هذه الخيارات lazy ويولّد أسماء Server بحسب موضع الخيار؛ لذلك Server 4 الحالي هو WatchLink 109638، لا استنتاجًا من اسم خادم Oscar.

الرابط المختار من `url`، و`deep_link` من نوع `tdmvideo` ويتضمن رابط CDN من الأصل نفسه. استخرجت الإضافة Cookie وUser-Agent من بيانات WatchLink، وطابقا الترويسات المرسلة؛ User-Agent يطابق `PLAY_UA` في تعديل OscarTV CloudStream الذي يضيف Cookie للحماية من فيديو التنويه. لم يرسل المزود Referer، والتعديل الأصلي لا يضيفه. أعاد طلب HLS محدود HTTP 200 بلا تحويل، وكان المحتوى قائمة VOD منتهية فيها 394 مدة `EXTINF` بإجمالي 3936 ثانية (65:36). لم يُطلب أي مقطع ولم يحدث تشغيل داخل مشغل؛ هذه البيانات لا تثبت المحتوى المرئي/المسموع. لم يظهر فيديو الدقيقة الواحدة في استجابة القائمة، لكن تأكيد الحلقة أو نفي تشغيل تحذير داخل المقاطع ما زال يحتاج تشغيلًا فعليًا.

لم يثبت عيب محلي في اختيار `url` أو استخراج بيانات الجلسة. اختبار القائمة دليل على مسار حلقة بطولها المعتاد، وليس ادعاءً بنجاح تشغيل House of the Dragon أو بأن المشكلة حُلّت بالكامل.

## مراقبة تحديثات التطبيق

`.github/workflows/oscar-release-monitor.yml` يفحص إصدار GitHub الرسمي يوميًا أو عند التشغيل اليدوي. يتحقق من digest، package/version، شهادة التوقيع، ومن إصدار JADX وبصمته المثبتة، ثم يفك المصدرين ويقارن مسارات API ومؤشرات التوقيع والنماذج وhandoff. تنتج `tools/oscar-release-diff.cjs` JSON يتضمن الملفات المتغيرة ومؤشرات التغييرات وأسبابًا محتملة لكون التغيير breaking. يرفق التشغيل ملف الفرق وbaseline مقترحًا كـartifact حتى إذا فشلت الاختبارات لاحقًا.

التشغيل لا يعدل baseline ولا manifest ولا ينشر plugin ولا ينشئ PR. كل تغيير شهادة أو package، وإزالة route أو مؤشر playback/signing، يتطلب مراجعة بشرية. لم يُشغّل workflow على GitHub بعد؛ تحققنا محليًا من أداة المقارنة فقط. موقع OscarTV يعلن مصدر تنزيل رسميًا، لذلك لا يلزم trigger رفع APK يدوي بديل في الوقت الحالي.

## الاختبارات وخطة الانتقال

اجتازت اختبارات Node الحتمية **80/80**. واجتاز اختبار Yume المحدد `PlayerPlaybackNetworkingTest` **3/3**، بما فيه تمرير Cookie وAuthorization وReferer على الأصل، حذفها عند التحويل إلى أصل آخر، وعزل ترويسات الترجمة. تشغيل مجموعة Android host كاملة شغّل 1616 اختبارًا: تعثر اثنان من `DownloadSubtitlesTest` (مذكوران كإخفاقين سابقين في سجل المشروع)، وتعثر `AndroidDownloadLifecycleTest.classMethod` أيضًا؛ لذلك لا تُنسب تلك النتائج إلى إصلاحات الشبكة دون مقارنة مستقلة بالنسخة السابقة. هذه الاختبارات لا تشغّل الإضافة داخل Android QuickJS ولا تثبت تشغيل المحتوى الفعلي. لم يُستخدم محاكي.

معرّف الإضافة `oscar` وAPI v2؛ رقم manifest هو `2.0.9`. يبقى `plugins/oscartv.js` متاحًا للعملاء التي خزنت manifest قديمًا. إصدار التطوير ليس تحققًا كاملًا من التشغيل: لم نشغّل الحلقة ولا نؤكد أن محتواها المرئي/المسموع هو الحلقة المطلوبة. لم يُشغّل workflow على GitHub بعد.

## قرار الجاهزية

هذا إصدار تطوير يثبت اتصال API الحالي وقائمة WatchLinks ووصول ترويسات Cookie/User-Agent إلى قائمة HLS بطول 65:36. لا نعلن أن مشكلة التشغيل حُلّت بالكامل: يلزم تشغيل الحلقة للتأكد من محتواها الفعلي وعدم ظهور التنويه أثناء تشغيل المقاطع. لا توجد قرينة على منع متعمد لعميل خارجي، ولا اختبار Android QuickJS أو تشغيل GitHub Actions لهذا التغيير.
